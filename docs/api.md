# Control-plane API

The HTTP process does not calculate throughput, fairness, or `tc` rules. A route calls a service. The service calls the pieces that are already tested:

```text
route
  → ClientService / MetricsService / PolicyService
    / AllocationService / QosService / EventService
      → MonitoringService.sample_once
      → BandwidthController.tick
           → congestion check and weighted allocator
           → QoSManager.apply_allocation or clear_all_rules
```

`POST /qos/apply` is one controller tick. The tick still refuses to reinstall an unchanged share, and it still waits out the cooldown. `POST /qos/clear` is an operator action: it deletes the lab qdiscs immediately. The next apply can still be held by the cooldown, so a clear does not become limit → remove → limit on the following sample.

OpenAPI is generated by FastAPI at `/docs` and `/openapi.json`.

## Run

```text
python -m bandwidth_manager.api
```

Default listen address is `127.0.0.1:8000`. The process loads `config/controller.example.yaml` and the monitor and QoS files named inside it, then reads counters with the existing Linux source. `enforced` is true only when `tc` accepts the commands. A dry run or a failed command returns HTTP 409 with `error.code` `not_enforced`.

## Environment

| Variable | Default | Meaning |
|---|---|---|
| `BW_DATABASE_PATH` | `data/bandwidth.sqlite` | SQLite file. Tests use `:memory:` |
| `BW_CONTROLLER_CONFIG` | `config/controller.example.yaml` | Loop knobs and, unless overridden, the other two files |
| `BW_MONITOR_CONFIG` | path inside the controller file | Client identity and counter interfaces |
| `BW_QOS_CONFIG` | path inside the controller file | Interfaces `tc` is allowed to touch |
| `BW_HOST` / `BW_PORT` | `127.0.0.1` / `8000` | Bind address |
| `BW_LOG_LEVEL` | `INFO` | Python log level |
| `BW_USAGE_BUCKET_SECONDS` | `60` | Width of each usage aggregate |
| `BW_USAGE_RETENTION_SECONDS` | `86400` | Drop usage buckets older than this |
| `BW_MAX_EVENTS` | `500` | Newest events kept |
| `BW_MAX_ALLOCATION_HISTORY` | `200` | Newest allocation decisions kept |
| `BW_CORS_ORIGINS` | empty | Comma-separated browser origins. CORS is off when this is empty |

## Resources

`GET /health` reports the process and the database. `dry_run` mirrors the QoS config.

`GET /clients` and `GET /clients/{client_id}` return identity, IP, MAC (null until a source provides one; the monitor does not read it), interface, namespace, connection status, current rates, installed allocation, policy, and aggregated usage. Status is `unknown` before the first sample, `online` when the latest sample included the client, and `offline` when that sample did not.

`GET /metrics` takes one real sample and returns the rates plus the retained usage buckets.

`GET /allocations` and the client `allocation_bps` field report the rates from `tc -json class show` when that command returns JSON. If it does not, they report the share this process last installed. A row left in SQLite after a restart is history only and is not reported as the current allocation.

`GET /policies` returns the shared capacity, thresholds, cooldown, tolerance, and each client's weight and optional min/max. `POST /policies` replaces the shared fields and the weights. Weights must name exactly the configured clients. `PUT /policies/{client_id}` replaces that client's weight and its min/max overrides. Null min or max means "use the shared value". The next tick reads these values from the same `ControlConfig` object the controller already uses.

`POST /qos/apply` runs one tick. `POST /qos/clear` removes lab HTB qdiscs. Both return the decision: utilization, congestion, previous share, new share, reason, and the `tc` argv that ran. `enforced` is false when nothing was installed.

`GET /events?limit=50` returns the newest stored events.

## Errors

Every error body is:

```json
{"error": {"code": "not_found", "message": "unknown client: client-z", "details": null}}
```

| Status | Code | When |
|---|---|---|
| 404 | `not_found` | Unknown client id |
| 422 | `validation_error` | Bad JSON, bad client id, or a policy the allocator would not accept |
| 409 | `not_enforced` | `tc` was asked to change and did not succeed, including dry-run |
| 500 | `internal_error` | Unexpected failure. The message is generic; the traceback stays in the log |

## What is stored

SQLite tables: `clients`, `control_policy`, `client_policy`, `current_allocation`, `allocation_history`, `events`, `usage_buckets`.

There is no table of raw samples. Each sample adds its byte delta into the current time bucket (`samples`, byte totals, and average bits per second). Buckets older than the retention window are deleted. Events and allocation history keep only the newest configured rows.

MAC is a column on `clients`. Seeding from the monitor config leaves it null. A later seed does not wipe a MAC that was already stored.

## What this process does not do

It does not reshape the host, and it does not invent a rate when the first sample has no previous counter. After a restart the in-memory view of installed `tc` rules starts empty, so the clients and allocations endpoints show no enforced share until the next successful apply. The database keeps the previous share in history. The next successful apply may send the same tree again.
